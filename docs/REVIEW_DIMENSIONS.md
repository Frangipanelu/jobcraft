# JobCraft 评审维度框架

> 本文档定义评审的完整维度、评估方法、检查清单，确保评估全面且可量化。

## 一、评审维度体系（7大维度 × 38个子项）

### 维度1：安全性（Security）- 权重 25%

| 子项 | 检查内容 | 评估方法 | 严重等级 |
|------|----------|----------|----------|
| 1.1 认证授权 | 是否有用户认证、Token 机制、权限控制 | 代码审查 + 渗透测试 | P0 |
| 1.2 数据隔离 | 多用户数据是否隔离、user_id 是否可篡改 | 接口测试 | P0 |
| 1.3 CORS 配置 | 是否限制来源、方法、头 | 配置审查 | P0 |
| 1.4 输入验证 | 是否有长度限制、类型校验、格式校验 | Fuzz 测试 | P0 |
| 1.5 SQL 注入 | 是否使用参数化查询、表名白名单 | SQL 注入测试 | P0 |
| 1.6 文件上传 | 文件名清洗、类型校验、大小限制 | 上传恶意文件测试 | P1 |
| 1.7 敏感信息 | API Key、密码是否硬编码、日志是否泄露 | 代码审查 | P0 |
| 1.8 错误处理 | 异常是否暴露堆栈、内部路径 | 异常触发测试 | P1 |
| 1.9 速率限制 | 是否有接口限流、防刷机制 | 压力测试 | P1 |
| 1.10 HTTPS | 是否强制 HTTPS、证书配置 | 网络配置审查 | P1 |

## 二、评估方法论

### 2.1 静态分析（Static Analysis）

```
工具链：
- Python: ruff, mypy, bandit (安全), pip-audit (依赖)
- TypeScript: tsc, eslint
- 依赖: npm audit, safety
```

### 2.2 动态测试（Dynamic Testing）

```
层级：
- 单元测试: pytest (目标 >80% 覆盖率)
- 集成测试: API 接口测试
- E2E 测试: Playwright (关键流程)
- 安全测试: OWASP ZAP / Burp Suite
- 性能测试: Locust / k6
```

### 2.3 人工审查（Manual Review）

```
检查项：
- 代码审查: 至少 2 人审查
- 架构审查: 架构师评审
- 安全审查: 安全专家评审
- 产品审查: 产品经理验收
```

### 2.4 渗透测试（Penetration Testing）

```
范围：
- SQL 注入
- XSS 攻击
- CSRF 攻击
- 文件上传漏洞
- 权限绕过
- 信息泄露
```

### 4.2 评分计算公式

```
总分 = Σ(维度权重 × 维度得分)

维度得分 = (子项得分总和 / 子项数量) × 10

子项得分标准：
- 0分：完全不满足，存在严重问题
- 3分：部分满足，有明显缺陷
- 6分：基本满足，有小问题
- 8分：良好，符合预期
- 10分：优秀，超出预期

上线标准：
- 总分 ≥ 70分
- 无 P0 级阻塞项
- P1 级问题 ≤ 5个
```
