# 06 — 面试准备增强与手动补录设计

## 背景

当前面试准备仅基于 JD + 经历卡生成预测题和答题要点，缺少：
- 公司调研（面试前了解目标公司）
- 已投简历上下文（面试官手里有你的简历）
- 逐字稿格式（开场/收尾/反问，不只是答题要点）
- 多轮面试衔接（一面复盘后二面升级）
- 手动补录（未用系统投递的面试无法使用）

---

## A. 手动补录投递（向导式）

### 问题

单纯在主页加「上传简历」按钮没有意义——简历上传只会抽取经历卡，不生成 JD 分析。而没有 JD 分析，后续面试准备就没有岗位上下文。

### 方案：主页内嵌 3 步向导

入口在求职路线页右上角 → 「📄 手动补录投递」，点击弹出 Modal 向导：

```
Step 1 ── 基本信息
  岗位名称 * | 公司 *
  [下一步]

Step 2 ── 上传已投简历
  上传 PDF/DOCX/MD → 调用 upload_resume 接口
    ├─ 解析简历文本
    ├─ 按现有 extract 逻辑拆成经历卡（落 experience_card 表）
    └─ 存 resume_raw_text（待会写入 submission.resume_markdown）
  [上一步] [下一步]

Step 3 ── JD 分析
  粘贴 JD 文本 → 调用 step1-ats-recommend 接口
    ├─ 返回 ATS 画像
    └─ 返回 job_analysis_id
  [上一步] [确认创建]

确认 → 后端创建 submission:
  position / company ✓
  resume_markdown = Step 2 提取的纯文本
  job_analysis_id = Step 3 的分析 ID
  is_manual = true
  status = "已投递"

跳转主页 → 新条目出现 → 用户可正常进入🎤面试准备
```

### 为什么是向导而不是一个表单提交

| 方式 | 问题 |
|------|------|
| 一个表单全填完 + 后端依次调 | 长时间无反馈，用户不知道进度 |
| 先上传简历再单独分析 | 流程割裂，用户不知道下一步要做什么 |
| 向导 | 每步有明确目标、即时反馈、可回溯 |

### 关键设计

- **Step 2 上传简历** = [复用] `POST /api/jobcraft/experience/upload`（已有路由，解析简历并抽卡）
- **Step 3 JD 分析** = [复用] `POST /api/jobcraft/job/step1-ats-recommend`（已有路由）
- **Step 2 → Step 3 的数据传递**：前端保存 resume_raw_text + card_ids，Step 3 确认时一并提交
- **后端新增路由**：`POST /api/jobcraft/submission/manual`，接收 `{position, company, jd_text, job_analysis_id, resume_markdown}`，创建投递并返回

### 文件变更

- `CareerRoutePage.tsx`：新增「手动补录投递」按钮 + Modal 向导（3 步组件）
- `server.py`：新增 `POST /api/jobcraft/submission/manual` 路由
- `db_tools.py`：`create_submission()` 支持 `is_manual` 参数
- `resume_submission` 表：新增 `is_manual` 字段

## B. 公司调研预加载

面试准备流程中，在用户选择轮次前先调取公司调研。

```
点击🎤面试准备（status >= 面试邀约）
  │
  ├─ 从 submission 取 company
  ├─ [复用] search_company(company) → Tavily 搜索 + LLM 汇总
  │   ├─ 7天缓存（company_research 表已有）
  │   ├─ 调研结果缓存在 interview_preps.company_research_json
  │   └─ 用户可点「刷新调研」强制重新搜索
  │
  └─ 进入选择轮次页面（调研摘要展示在顶部）
```

### 文件变更

- `interview_preps` 表：新增 `company_research_json` + `company_research_at`

## C. 面试逐字稿增强

改写 prompt，输入增加公司调研 + 已投简历，输出从预测题升格为完整逐字稿。

### 输入

| 当前 | 新增 |
|------|------|
| JD 文本 | + 公司调研摘要 |
| 经历卡（润色版本优先） | + 已投简历全文（resume_markdown） |
| 维度要求 | + 上一轮复盘摘要（仅二面及以后） |

### 输出结构

```
1. 开场自我介绍（公司调研定制 + JD 岗位贴合）
2. 维度问题逐字稿（D1-D8 × N）
   ┌──────────────────────────────────┐
   │ 面试官：请介绍你在XX项目中的角色    │
   │                                  │
   │ 我：我在该项目中担任……              │
   │    （结合简历数据 + 公司业务语境）    │
   │    具体来说……                      │
   │    结果是……                        │
   └──────────────────────────────────┘
3. 针对该公司的反问（3-5 个，基于调研）
4. 收尾模板
```

### 文件变更

- `interview_pre.py`：重写 `_build_interview_prompt()`，新增 `company_research` / `resume_markdown` / `prev_review_summary` 参数
- `server.py`：面试准备路由自动传参（查 submission 拿 resume_markdown，查 company_research，查最新 review）

## D. 多轮衔接

```
一轮 → 复盘完成 → 点击🎤面试准备 → 选择「二面」
  ├─ 查找该 submission 下最新一条 review record
  ├─ 提取 review 中的 [优势] [劣势] [弱项]
  └─ prompt 追加："上一轮复盘发现你在XX维度较弱，本次重点：…"
```

### 文件变更
- `interview_pre.py`：`generate_interview_prep()` 新增 `previous_review_summary: Optional[str]`

## E. 前端面试准备页面调整

`InterviewPrepPage.tsx` 流程：

```
挂载
  ├─ 加载 submission → position / company / jd_text / resume_markdown
  ├─ 调 search_company(company) → 展示调研摘要面板（折叠/展开）
  │   └─ 「刷新调研」按钮 → 调 search_company(company, force=True)
  ├─ 选择面试轮次
  ├─ 「生成面试准备稿」
  │   └─ 支持多轮：检测上一轮复盘 → 提示「检测到上一轮复盘，将针对性强化」
  └─ 展示结果
      ├─ 逐字稿全文渲染（full_version）
      └─ 导出 MD 按钮 → 下载 .md 文件
```

### 文件变更
- `InterviewPrepPage.tsx`：调研面板 + 逐字稿全文 + 导出 MD
- `api.ts`：新增 `exportPrepMd()` / `exportReviewMd()` （可选，MD 可直接前端拼接下载）

## 数据变更

```sql
ALTER TABLE resume_submission
  ADD COLUMN is_manual TINYINT(1) DEFAULT 0;

ALTER TABLE interview_preps
  ADD COLUMN company_research_json JSON,
  ADD COLUMN company_research_at   DATETIME;
```

## 无需改动的部分

- `CompanyResearchInfo` / `CompanyResearchResult` Schema
- `InterviewPrepResult` Schema（`full_version` + `html_content` 已有）
- `search_company()` 函数（已有 7 天缓存，直接复用）
- Tavily API Key（已有配置）
- Word 导出 → 砍掉，仅 MD

## 设计决议

1. **手动补录 = 3 步向导**，每步调用已有接口，不新增复杂逻辑
2. **Word 导出不做**，MD 导出在浏览器端拼接下载即可
3. **多轮衔接只带复盘摘要**，不重跑公司调研（7 天缓存）
4. **面试逐字稿分轮次独立存储**，同一 submission 可有多份 interview_preps
