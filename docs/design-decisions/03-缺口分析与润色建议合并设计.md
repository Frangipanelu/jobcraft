# 03 — 缺口分析 + 润色建议合并设计

## 为什么合并

之前的设计是两步：

```
缺口分析（LLM）→ 产出一份缺失项清单
润色建议（LLM）→ 读同一份数据再做一遍分析
```

这两步的输入完全相同（JD + 卡片），输出有因果关系（缺什么 → 怎么补）。拆成两步不仅多一次 LLM 调用，而且两步之间信息断裂——第一步说「缺用户增长」，第二步又要重新理解「缺用户增长」是什么意思。

合并为一步后，LLM 在分析缺口的同时直接给出补法，每一条缺失都有对应的操作建议。

---

## 单卡输出的三层结构

对每张卡，LLM 需要输出三个层次的信息：

### Layer 1: 评分
- `score`: 0-100，这张卡与 JD 的匹配度
- 融合规则：本地关键词匹配 × 0.4 + LLM 语义评分 × 0.6（已有逻辑不变）

### Layer 2: 覆盖诊断
- `matched`: 这张卡已经覆盖了哪些 JD 要求
- `missing`: 这张卡缺了哪些 JD 要求（能为空，表示完全覆盖）
- 对比现有算法只输出**全局缺失**（所有卡加起来缺什么），现在要细到**每张卡缺什么**

### Layer 3: 行动指令
每条 `missing` 都要对应一个 `action`，告诉前端怎么展示：

| action 类型 | 含义 | 前端 UI | 数据 |
|-------------|------|---------|------|
| `polish` | 卡里有相关内容但表述不够好，只需润色 | 展示改写建议 + 可编辑 diff 框 | `rewrite_suggestion: "将'负责增长'改为'通过A/B测试优化转化链路，DAU提升40%'"` |
| `supplement` | 卡里缺乏相关内容，需要新增一段 | 展示补充建议 + 操作步骤 + 空白编辑框 | `supplement_suggestion: "建议补充一段用户分层经验：1. 用RFM模型划分 2. 针对性策略设计 3. 效果量化"` |
| `good` | 已覆盖且表述充分 | 仅展示绿标，无需操作 | `score >= 80` |

## 全局建议

除了每张卡的细节，LLM 还输出一个全局层面的补充建议列表：

```json
{
  "global_suggestions": [
    {
      "missing_ability": "AIGC 产品经验",
      "priority": "high",
      "action": "建议新建一张经历卡，描述 AI 相关项目经历",
      "steps": [
        "1. 项目背景：什么场景下需要引入 AI 能力",
        "2. 你的角色：产品方案设计 / 模型评估 / 效果验收",
        "3. 量化结果：效率提升 / 用户指标变化 / 业务收益"
      ]
    },
    {
      "missing_ability": "跨团队协作经验",
      "priority": "medium",
      "action": "在已有卡片的结果段补充跨部门协作描述",
      "steps": [
        "1. 与哪些团队协作（算法 / 工程 / 运营）",
        "2. 协作中的关键决策",
        "3. 协作带来的业务结果"
      ]
    }
  ]
}
```

全局建议和卡片建议的区别：
- 卡片建议只针对已选中的卡
- 全局建议是在所有已选卡片都覆盖不了的情况下，提示用户**新建经历卡**或**补充新经历**

---

## Prompt 设计概览

合并后的 LLM 调用接受：
- JD 要求列表（由 ATS 解析提前产出）
- 所有选中的经历卡（包含 raw_text + tags + ai_structured）

输出结构化 JSON，每个卡片一个条目，带匹配详情 + 行动指令。

这个 prompt 的关键约束：
1. `polish` 建议必须基于卡片现有内容改写，不能编造不存在的事实
2. `supplement` 建议必须明确写出操作步骤（写什么、怎么写），不能空泛说「建议补充」
3. 每条 missing 都必须有对应的 action，不能只列问题不给解法

## 总流程（更新版）

```
                    ┌──────────┐
                    │  粘贴 JD  │
                    └────┬─────┘
                         ▼
                  ┌──────────────┐
                  │  ATS 拆解     │ ← 一次 LLM 调用，产出岗位画像
                  │  展示岗位画像  │
                  └──────┬───────┘
                         ▼
              ┌──────────────────────┐
              │  AI 推荐相关经历卡    │ ← 二次 LLM 调用，按岗位画像从用户卡片池推荐
              │  用户勾选审批         │
              └──────┬───────────────┘
                     ▼
          ┌──────────────────────────┐
          │  缺口分析 + 润色/补充建议  │ ← 三次 LLM 调用（合并，最核心）
          │  用户逐条编辑确认         │   每张卡：评分 + 覆盖诊断 + 行动指令
          └──────┬───────────────────┘
                 ▼
          ┌────────────────┐
          │  生成简历 MD    │ ← 四次 LLM 调用，取最终版卡片拼成简历
          └────────────────┘
```

**一共 4 次 LLM 调用**，每次数据依赖清晰，没有冗余。
