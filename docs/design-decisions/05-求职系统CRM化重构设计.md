# 05 — 求职系统 CRM 化重构设计

## 问题

当前四步线性流程（经历→岗位分析→面试准备→面试复盘）假设「1 个岗位分析 → 1 个面试」，但实际：

```
投 10 份简历 → 面 3 家 → 复盘 2 家
                ↑           ↑
            只有这 3 家需要面试准备
            其他 7 家只需要改简历
```

同时 JD 分析被三个场景复用（改简历、面试准备、复盘），不应绑死在一步里。

## 设计原则

1. **独立工作台而非线性流程** — 每个功能是独立页面，用户按需跳转
2. **投递记录作为 pipeline 核心** — 一条投递记录贯穿投简历→面试→复盘
3. **JD 分析是原子功能** — 不绑定卡片，不绑定流程步骤
4. **松外键** — 实体间尽量用 `source_type + source_id` 而非硬 FK，避免迁移成本

## 实体关系图

```
experience_card (N 张)
      │
      └── card_versions (N 版/卡)
              │ version_type=polished
              │ source_type=job_analysis, source_id=job_analysis.id
              │
              ▼
        resume_submission (pipeline 核心)
          ├─ job_analysis_id (nullable, 从已分析的机会创建)
          ├─ position / company / jd_text
          ├─ resume_markdown (实际投出的简历全文)
          ├─ card_version_ids JSON (快照: 用了哪些润色版本)
          ├─ status: submitted → 面试邀约 → 一面 → 二面 → offer/已关闭
          │
          ├── interview_preps (面试准备稿)
          │     └── submission_id → resume_submission.id
          │         (不再 FK job_analysis)
          │
          └── interview_records (面试复盘记录)
                └── submission_id → resume_submission.id
                    round_label 标注是第几面
```

## 表设计

### `job_analysis` — 改为原子分析记录（独立实体）

```sql
CREATE TABLE job_analysis (
  id             INT AUTO_INCREMENT PRIMARY KEY,
  user_id        INT DEFAULT 1,
  position       VARCHAR(200) NOT NULL,       -- 用户输入的岗位名
  company        VARCHAR(200) DEFAULT '',
  jd_text        LONGTEXT NOT NULL,           -- JD 原文
  ats_profile    JSON,                        -- ATS 解析结果
  dimension_requirements JSON,                -- D1-D8 等级
  raw_summary    TEXT,                        -- JD 摘要（可选的）
  created_at     TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**变化**：
- 删掉 `match_score`, `gap_analysis`, `jd_requirements` 等步骤耦合字段
- 移除 `selected_card_ids` 关联（不再需要，卡片选择是 submission 的事）
- 新增 `ats_profile` 和 `raw_summary` 作为核心产物

### `resume_submission` — 新增 pipeline 实体

```sql
CREATE TABLE resume_submission (
  id               INT AUTO_INCREMENT PRIMARY KEY,
  user_id          INT DEFAULT 1,
  job_analysis_id  INT,                      -- nullable, 从哪个分析创建的
  position         VARCHAR(200) NOT NULL,
  company          VARCHAR(200) DEFAULT '',
  jd_text          LONGTEXT,                 -- 从分析带过来或手动填
  resume_markdown  LONGTEXT,                 -- 实际投出的简历全文
  resume_file_path VARCHAR(500),             -- 上传的文件路径（可选）
  card_version_ids JSON,                     -- [version_id, ...] 快照
  status           VARCHAR(32) DEFAULT '已投递',  -- 已投递/面试邀约/一面/二面/Offer/已关闭
  notes            TEXT,
  created_at       TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at       TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_user_status (user_id, status),
  KEY idx_job_analysis (job_analysis_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### `interview_preps` — 调整外键关联

当前 `job_analysis_id` 不改名（存量数据兼容），新增 `submission_id`：

```sql
ALTER TABLE interview_preps ADD COLUMN submission_id INT;
ALTER TABLE interview_preps ADD KEY idx_submission (submission_id);
```

新生成的面试准备稿写 `submission_id`。旧数据 `job_analysis_id` 仍可查。

### `interview_records` — 加入 submission_id

```sql
ALTER TABLE interview_records ADD COLUMN submission_id INT;
ALTER TABLE interview_records ADD COLUMN round_label VARCHAR(32) DEFAULT '';  -- 一面/二面/HR面
ALTER TABLE interview_records ADD KEY idx_submission (submission_id);
```

**每条投递记录是一个横向卡片**，包含：
- 左侧：岗位 + 公司 + 状态切换下拉 + 时间线摘要
- 右侧：5 个步骤按钮，每个显示当前进度（已分析 / 已润色 / - / 就绪 / 已完成）
- 点击按钮跳转到对应功能页，自动选中当前投递

**状态流转**：用户在下拉框手动切换（「已投递」→「面试邀约」→「一面」→「二面」→「Offer」/「已关闭」），触发对应按钮的可用性变化。
- 「面试邀约」之前：🎤准备不可用（灰色），📝复盘不可用
- 「面试邀约」之后：🎤准备可用
- 「一面」之后：📝复盘可用

### 功能页 1：JD 分析库（独立可用）

从侧边栏进入，也可从投递详情的「JD分析」按钮跳转（自动选中该投递的 JD）：

```
┌─────────────────────────────────────────────────────────────┐
│  JD 分析库  [+ 新建分析]                                      │
│                                                             │
│  ── 新建 ──                                                  │
│  岗位名称: [input]                                           │
│  公司: [input] (可选)                                        │
│  JD 原文: [textarea]                                         │
│  [开始分析]                                                  │
│                                                             │
│  分析结果:                                                   │
│  ┌─────────────────────────────────────────────────────────┐│
│  │ ATS 画像                                                  ││
│  │ 岗位: 高级产品经理 / 经验: 3-5年 / 学历: 本科以上         ││
│  │ 硬技能: 用户增长, A/B测试, 数据分析                       ││
│  │ 软技能: 跨部门沟通, 项目管理                              ││
│  │ D2 业务理解 L4 | D5 落地执行 L4 | D3 问题拆解 L3 ...     ││
│  └─────────────────────────────────────────────────────────┘│
│                                                             │
│  操作: [润色卡片 →]  [创建投递 →]                              │
│                                                             │
│  ── 列表 ──                                                  │
│  | 时间        | 岗位           | 公司    | 关联投递 | 操作   │
│  | 07-28 | 高级产品经理 | 字节 | 1 个投递 | [复用] [删除]    │
│  | 07-25 | 产品专家     | 腾讯 | 0       | [复用] [删除]    │
└─────────────────────────────────────────────────────────────┘
```

**关键点**：即使没有创建投递记录，JD 分析也可以独立完成并存着。「润色卡片」和「创建投递」是按钮，用户自己选时机。JD 分析可被多个投递复用（同一个人投不同公司但 JD 相似）。

│  ── 选中一张 → 右侧抽屉 ──                                   │
│  标题: [input]                                               │

- 用户选卡 → 点 [AI 润色建议] → 查看 → 修改 → 保存（存 card_versions）

## 页面间跳转关系

```
           ┌─────────────────┐
  ┌────────┤ 求职路线（主页）  ├────────────┐
  │        └────────┬────────┘            │
  │                 │                     │
  ▼                 ▼                     ▼
JD 分析库        面试准备              面试复盘
  │                                     ▲
  └── [创建投递] ──→ 求职路线新条目 ────┘
  └── [润色卡片] ──→ 经历卡页
```

所有跳转都带上下文（自动选中相关记录），不跳新标签页。

## 新增路由

| 路由 | 页面 | 说明 |
|------|------|------|
| `/` | 求职路线主页 | 默认展示所有投递记录 |
| `/jd-analysis` | JD 分析库 | 独立工作台 |
| `/cards` | 经历卡管理 | （现有 ExperiencePage） |
| `/prep/:submissionId` | 面试准备 | 从投递详情跳转 |
| `/review/:submissionId` | 面试复盘 | 从投递详情跳转 |
| `/prep/:submissionId/:round` | 面试准备 | 指定轮次 |
| `/review/:submissionId/:round` | 面试复盘 | 指定轮次 |

## 变更清单

| 组件 | 变化 |
|------|------|
| `job_analysis` 表 | 精简为原子分析记录，删匹配/缺口字段，剥离卡片关联 |
| `resume_submission` 表 | 新增 pipeline 实体 |
| `interview_preps` 表 | 新增 `submission_id`（兼容旧 `job_analysis_id`） |
| `interview_records` 表 | 新增 `submission_id` + `round_label` |
| 面试准备页 | 改为从投递记录进入，顶部带「返回」 |
| 面试复盘页 | 改为从投递记录进入，顶部带「返回」 |
| 主页 | 求职路线: 时间线布局，每条投递含状态 + 按钮矩阵 |
| JD 分析库 | 独立页面，「润色卡片」和「创建投递」是功能按钮 |
| 经历卡页 | 增加版本历史面板 |

## 不做的

- 不改 `card_versions` 表结构（已满足需求）
- 不改 `prep_editions` 表（现有够用）
- 不删面试准备的 `job_analysis_id` 字段（兼容旧数据）
