# 07 — 主页卡片 UI 顺序与引导设计

## 按钮顺序（两条线统一）

当前顺序：`JD分析 → 润色卡片 → 简历 → 🎤面试准备 → 📝复盘`

改为按**用户操作流程**排序：

```
📄 简历 → 🔍 JD分析 → 📝 润色卡片 → 🎤 面试准备 → 📝 复盘
```

理由：无论哪条线，用户第一步都是「简历」——要么看系统生成的简历，要么上传已投简历。简历就绪后才做 JD 分析。

---

## 按钮状态定义

四种状态：

| 状态 | 样式 | 含义 |
|------|------|------|
| **todo** | 蓝色实心+脉冲 | 当前需要用户操作的步骤 |
| **done** | 绿色边框 | 已完成，可点击查看 |
| **locked** | 灰色半透明 | 前置条件未满足，hover 显示引导文字 |
| **ready** | 默认样式 | 条件满足，等待用户主动使用 |

---

## 线A（系统生成）全状态

卡片创建时就全部就绪：

```
📄 简历： [done]  查看简历
🔍 JD分析：[done]  查看分析
📝 润色：[done]  已润色 X 张
🎤 面试准备：[locked]  需状态≥面试邀约
📝 复盘：[locked]  需状态≥一面
```

---

## 线B（手动上传）逐状态

### 状态 1：刚创建（仅填了岗位+公司）

```
📄 简历：[todo]  上传已投简历    ← 蓝色脉冲，唯一可点
🔍 JD分析：[locked]  hover:"请先上传简历"
📝 润色：[locked]  hover:"简历上传后自动抽取经历卡"
🎤 面试准备：[locked]  hover:"需状态≥面试邀约"
📝 复盘：[locked]  hover:"需状态≥一面"
```

### 状态 2：简历已上传

```
📄 简历：[done]  查看简历       ← 绿色 ✓
🔍 JD分析：[todo]  粘贴 JD      ← 蓝色脉冲，下一步操作
📝 润色：[done]  已自动抽取 N 张  ← 绿色 ✓
🎤 面试准备：[locked]
📝 复盘：[locked]
```

点击「粘贴JD」→ 弹窗输入 JD → 调 step1-ats-recommend

### 状态 3：JD 分析完成

```
📄 简历：[done]  查看简历
🔍 JD分析：[done]  查看分析
📝 润色：[done]  已自动抽取 N 张
🎤 面试准备：[locked]  需状态≥面试邀约
📝 复盘：[locked]
```

此时**两条线同态**，之后行为完全一致。

## 关键交互细节

### 上传简历弹窗（点击「上传已投简历」）

```
┌──────────────────────────────┐
│  上传已投简历                  │
│                              │
│  岗位 *  [________________]   │
│  公司    [________________]   │
│                              │
│  [选择文件] 支持 PDF/DOCX/TXT │
│                              │
│  或直接粘贴文本：              │
│  [┌────────────────────┐]    │
│  [│                    │]    │
│  [└────────────────────┘]    │
│                              │
│  [确认上传]                   │
└──────────────────────────────┘
```

上传后后端：
1. 解析文件 → `resume_markdown`
2. 调用 extract 逻辑 → 抽取经历卡（插入 experience_card 表）
3. 创建 submission（is_manual=true, status=已投递）

### 粘贴 JD 弹窗（点击「粘贴 JD」）

```
┌──────────────────────────────┐
│  JD 分析                      │
│                              │
│  粘贴 JD 原文：                │
│  [┌────────────────────┐]    │
│  [│                    │]    │
│  [└────────────────────┘]    │
│                              │
│  [开始分析]                   │
└──────────────────────────────┘
```

调 step1-ats-recommend，更新 submission.job_analysis_id。

### 润色卡片按钮 hover 逻辑

| 条件 | 显示文字 |
|------|----------|
| 经历卡=0 且 JD分析未完成 | "简历上传后自动抽取经历卡" |
| 经历卡=0 且 JD分析已完成 | "暂无经历卡，去创建 →"（可点击跳转）|
| 经历卡>0 | "已自动抽取 N 张经历卡" |

## 总结

| | 线A（系统生成） | 线B（手动上传） |
|---|---|---|
| 简历按钮 | 查看简历 ✓ | 上传已投简历 → 查看简历 |
| JD分析按钮 | 查看分析 ✓ | 粘贴 JD → 查看分析 |
| 润色按钮 | 已润色 X 张 ✓ | 已自动抽取 N 张 ✓ |
| 面试准备 | 🔒 需面试邀约 | 同左 |
| 复盘 | 🔒 需一面 | 同左 |
| 工作流 | 无额外操作 | 比线A多两步：上传简历 + 粘贴JD |
